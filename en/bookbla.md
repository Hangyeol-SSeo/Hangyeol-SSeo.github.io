<h1 style="font-size: 2.8rem; margin-bottom:8px">Motivation Behind the Service</h1>

<p>
I believe that in the future, more and more people will meet others through the internet.
However, most dating apps today only show appearance and are used for short-term encounters.
<br/>
So I asked: what if people could have meaningful connections online by looking at each other's values instead of just appearances?
I believed that "books" were the best medium to draw out one's values, and we built a meaningful matching service centered around books.
</p>

<h1 style="font-size: 2.8rem; margin-bottom:8px">Key Features</h1>

<div class="feature-grid" style="display: grid; grid-template-columns: repeat(auto-fit, minmax(250px, 1fr)); gap: 20px; margin: 20px 0;">
  <div style="background: #fff; border: 2px solid #e0e0e0; padding: 20px; border-radius: 8px;">
    <h3 style="margin-top: 0;">📌 Book Registration</h3>
    <p style="color: #666;">Users select a book that represents their values and register it in their bookshelf along with a review</p>
    <ul>
      <li>Implemented using the Aladin Book API</li>
      <li>Users select from given prompts to write a book review</li>
      <li>AI-assisted review feature — book registration rate increased by 10%+</li>
      <li>Matching algorithm operates based on registered books</li>
    </ul>
  </div>

  <div style="background: #fff; border: 2px solid #e0e0e0; padding: 20px; border-radius: 8px;">
    <h3 style="margin-top: 0;">📌 Chat</h3>
    <p style="color: #666;">Real-time chat powered by Sendbird for communication with matched partners</p>
    <ul>
      <li>1:1 chat room auto-created upon postcard (match request) acceptance; read/unread indicators</li>
      <li>Image and book info sharing</li>
      <li>Push notifications (foreground/background handled separately)</li>
      <li>Inappropriate conversation reporting</li>
      <li>Group chat rooms for users sharing similar interests</li>
    </ul>
  </div>

  <div style="background: #fff; border: 2px solid #e0e0e0; padding: 20px; border-radius: 8px;">
    <h3 style="margin-top: 0;">📌 Postcard (Match Request)</h3>
    <p style="color: #666;">Send postcards to initiate a match with someone you're interested in</p>
    <ul>
      <li>Send a postcard with a greeting mentioning what stood out in their book</li>
      <li>Chat room is created only after the postcard is accepted</li>
      <li>Postcards can be kept in the mailbox for up to 5 days</li>
    </ul>
  </div>

<h1 class="growth-section-header" style="font-size: 2.8rem; margin-bottom:8px">🌱 Adversity & Growth</h1>

<div class="growth-card" style="background: #f5f5f5; padding: 30px; border-radius: 12px; margin: 20px 0; font-size: medium">
  <h2 style="color: #222222">✅ The Speed of Users</h2>
  <b>Problem</b>: Multiple reports of email verification failures <br/>
  <b>Cause</b>: When users switched the app to background <b>immediately</b> after calling the email-send API, the timer didn't start → verification code input field was disabled <br/>
  <b>Solution</b>: Simplified API logic; moved timer/input activation earlier in the flow <br/>
  <b>Lesson</b>: Strengthened QA processes to account for unexpectedly fast user behavior <br/>
</div>

<div class="growth-card" style="background: #f5f5f5; padding: 30px; border-radius: 12px; margin: 20px 0; font-size: medium">
  <h2 style="color: #222222">🔗 Deep Linking + UTM Implementation</h2>
  <b>Problem</b>: Firebase Dynamic Links service was discontinued <br/>
  <b>Solution</b>: Combined LimeLink's deep linking with a custom serverless UTM tracking service <br/>
  <b>Architecture rationale</b>: Not using paid media at the time; low predicted traffic volume made serverless cost-effective and easy to scale later <br/>
  <b>Lesson</b>: Researched cost efficiency and scalability of serverless architecture; built the architecture hands-on <br/>
  <a href="https://limelink.org/" target="_blank" style="display: inline-block; margin-top: 10px; padding: 8px 16px; background: #222222; color: white; text-decoration: none; border-radius: 6px; font-size: 14px;">🔗 limelink.org</a> <br/>
  <img src="/assets/serverless_architecture.png" alt="Serverless Architecture" style="width: 600px; margin-top: 20px; border-radius: 8px;" />
</div>

<div class="growth-card" style="background: #f5f5f5; padding: 30px; border-radius: 12px; margin: 20px 0; font-size: medium">
  <h2 style="color: #222222">💰 Payment System & Bugs</h2>
  <b>Problem</b>: The initial payment system failed to properly deliver purchased items <br/>
  <b>Solution</b>: Implemented a payment processing listener at the app's top-level component, ensuring smooth payment handling even during background transitions <br/>
  <b>Lesson</b>: Realized payment features require thorough testing; became aware of edge cases like weak internet, app crashes, and background transitions <br/>
</div>

<div class="growth-card" style="background: #f5f5f5; padding: 30px; border-radius: 12px; margin: 20px 0; font-size: medium">
  <h2 style="color: #222222">📤 Adopting Expo Update (Code Push)</h2>
  <b>Problem</b>: Building and submitting for review took too long, creating a deployment bottleneck; build costs were high <br/>
  <b>Solution</b>: Adopted Code Push for real-time deployment; free for under 1,000 MAU <br/>
  <b>Lesson</b>: Learned the differences between standard deployment and Code Push; researched Code Push pricing models <br/>
  <b>Further improvements</b>: Enabled Code Push on background→foreground transitions; added update timing controls; added forced vs. optional updates per version <br/>
</div>

<div class="growth-card" style="background: #f5f5f5; padding: 30px; border-radius: 12px; margin: 20px 0; font-size: medium">
  <h2 style="color: #222222">📋 Server Maintenance for a Live Service</h2>
  <b>Problem</b>: Needed to display a maintenance screen when the live server is down or being updated; users were confused without it <br/>
  <b>Solution</b>: Implemented maintenance page switching using Firebase Remote Config <br/>
  <b>Lesson</b>: Learned how to control the app through third-party systems even when the server is down <br/>
</div>

<div class="growth-card" style="background: #f5f5f5; padding: 30px; border-radius: 12px; margin: 20px 0; font-size: medium">
  <h2 style="color: #222222">📱 Foreground & Background Notification Handling</h2>
  <b>Problem</b>: Needed to display chat notifications differently for foreground (in-app) and background (push) states <br/>
  <b>Solution</b>: Separated foreground and background listeners and placed them at the highest-level component <br/>
  <b>Lesson</b>: Gained understanding of FCM, APNs, Expo Notification, and Sendbird notification systems <br/>
</div>

<div class="growth-card" style="background: #f5f5f5; padding: 30px; border-radius: 12px; margin: 20px 0; font-size: medium">
  <h2 style="color: #222222">🍡 Props Drilling Refactoring</h2>
  <b>Problem</b>: Breaking components into smaller pieces led to props drilling issues <br/>
  <b>Solution</b>: Implemented proper state management using React Context API and Zustand <br/>
  <b>Lesson</b>: Learned about various approaches to avoid unnecessary deep prop passing <br/>
</div>

<div class="growth-card" style="background: #f5f5f5; padding: 30px; border-radius: 12px; margin: 20px 0; font-size: medium">
  <h2 style="color: #222222">🔥 GitHub Kanban Board & Milestones</h2>
  Created milestones defining sprint tasks and used Kanban boards to distribute work and share status with team members. <br/>
  Conducted daily scrums to share daily goals and celebrate "good & new" moments. <br/>
</div>
